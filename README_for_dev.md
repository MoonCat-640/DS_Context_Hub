# 任务：Deepseek网页版聊天记录压缩归档工具

## 1、任务概述

​	近日由于显卡不足，deepseek（以下简称ds）开始对网页端用户的每日聊天量和长上下文记录实行限制，导致很多用户不能像以往那样使用ds网页端。但ds官方给出了一个解决方案：用户下载Deepseek Harness或其他harness，然后从网页端导出聊天记录（.zip），随后加载进harness中继续聊天。不过，这份聊天记录本身比较大，其他harness也未必能读懂。你要做的，就是开发一个工具，可以读取这个zip，并将其中的内容压缩（类似/compact指令），针对每个聊天记录生成一个记录关键内容的.md文件，便于在Deepseek Harness或Claude Code中导入并接续聊天。

## 2、工具的主要功能

### (1)清洗与归档

​	程序读取一个从ds网页端官方导出的，记录了多个聊天记录的.zip压缩包，然后根据其中的索引等信息，对每一个聊天进行清洗，保留关键的聊天内容、代码、设定等信息，去掉其中的套话（如外交性、礼节性的信息，包括用户的提示词和AI的回答），只保留干货。

​	建议：使用python写一个小的正则，但是要达到比较好的效果，或者调用小模型处理。优先python正则判断

### (2)接入LLM

​	完成信息的读取后，弹出提示框，让用户选择使用的LLM（支持Deepseek、chatGPT、Qwen、文心一言、Gemini、Claude六个平台），并输入API Key，该软件自动检测API Key是否可用，对于可用的，调用对应平台价格最低的模型，对于不可用的，弹出提示框告知用户该API Key不可用。

### (3)让用户选择接收数据的harness

​	弹出窗口，让用户选择最终接收聊天数据的harness(支持Codex、Claude Code、Deepseek Harness、OpenCode四者)，为决定最后以什么形式给出复用材料做准备。

### (4)让用户选择需要继续的聊天

​	为避免用户tokens的浪费，读取完聊天记录后，生成一个可以选择的列表，以可选标签页的形式展示读取到的聊天记录和记录的名字信息，让用户可以勾选需要继续的聊天。

### (5)调用LLM压缩聊天记录

​	针对每个聊天，程序分别调用LLM对其进行compact的操作，由用户给出的API背后的模型判断如何压缩聊天并给出最终的压缩结果。

思路：写一个程序，调用大模型 API（比如便宜的 DSV4.1 Flash），把清洗后的记录总结成一份**结构化的 Markdown**。

Prompt 示例：“你是一个技术档案管理员。请将以下对话总结为：1. 核心需求；2. 踩过的坑及解决方案；3. 最终采用的代码/架构；4. 待办事项。不要输出任何客套话。”

产出物：一份几百字到一两千字的 `.md` 简报（每个聊天分别有１份）。

这一步全部由用户选定的模型进行操作，程序只提供对外部模型的接入服务

### (5)输出可复用材料

​	程序针对用户指定的不同harness，整理出对应的移植记忆文件，并引导用户将文件放到正确的存放位置。
